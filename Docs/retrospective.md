# Project Retrospective – Personal/Professional Portfolio Website

## Project Overview

For this project, I created a personal/professional portfolio website to introduce myself, share my educational and professional interests, and showcase projects and skills. I used HTML and CSS to build the website and GitHub Pages to publish it online.

The purpose of this retrospective is to reflect on the project process and identify what went well, what challenges occurred, and what I would change if I completed the project again.

---

# 1. What Went Well?

Several parts of the project went well.

### Learning HTML and CSS

One of the most successful parts of the project was learning how HTML and CSS work together. HTML allowed me to create the structure and content of the website, while CSS allowed me to control the appearance and layout.

At the beginning of the project, I had limited experience with coding. By the end of the project, I was more comfortable creating HTML elements, linking CSS files, adding images, creating links, and changing the appearance of the website.

### Creating a Professional Design

I was able to create a simple and professional design for my portfolio. I used a consistent color scheme and organized the information into sections so visitors could easily understand who I am and what I am working toward professionally.

### Using GitHub

Another successful part of the project was learning how GitHub can be used to store and publish a website. Creating a repository and using GitHub Pages helped me understand how websites can be moved from a local computer to an online environment.

### Problem Solving

The project also helped me improve my problem-solving skills. When something did not work, such as an image or link not displaying correctly, I had to investigate the problem and make changes to the code.

These experiences helped me understand that programming often involves testing, finding errors, and making improvements rather than getting everything correct on the first attempt.

---

# 2. What Went Wrong?

Although the project was successful overall, I experienced several challenges.

### Images Did Not Always Display Correctly

One problem I encountered was getting an image to display correctly on the website. The image file was saved in the project folder, but the website initially did not display it.

The problem required me to check the image filename, file location, and HTML code. This showed me how important file organization and accurate file paths are when working with websites.

### Links and Embedded Content

I also experienced problems when adding links and other website elements. Some of my initial HTML code was not structured correctly, which caused the link or content to not work as expected.

This was a learning experience because it showed me that HTML elements need to be used correctly and nested in the appropriate way.

### Understanding GitHub Pages

Publishing the website through GitHub Pages was another area that required some learning. There were several steps involved, including creating the repository, adding files, committing changes, and configuring the website for publication.

At first, the process seemed complicated, but working through each step helped me understand the relationship between my local files, GitHub, and the published website.

### Time Management

Another challenge was managing the project along with other coursework. Some tasks took longer than I originally expected, especially troubleshooting technical problems.

This demonstrated the importance of allowing extra time for testing and unexpected problems.

---

# 3. What Would I Do Differently?

If I completed this project again, I would make several changes.

### Plan the Website Before Coding

I would spend more time planning the website structure before beginning to write code. I would create a basic outline showing the sections, navigation, images, and content that I wanted to include.

This would make the development process more organized and reduce the amount of time spent changing the structure later.

### Organize Files From the Beginning

I would also create a clear file structure before starting the project. For example, I would create an images folder and make sure all image filenames were simple and consistent.

This would make it easier to reference images in the HTML and reduce the possibility of broken image links.

### Test More Frequently

I would test the website after completing each major section instead of waiting until the end.

For example, after adding an image, I would immediately check whether it displays correctly. After adding a link, I would test the link immediately.

This would make it easier to identify problems because I would know exactly which change caused the problem.

### Allow More Time for Troubleshooting

I would also schedule additional time for troubleshooting. Technical problems can take longer to solve than expected, especially when learning a new technology.

Building extra time into the project schedule would reduce stress and make it easier to complete the project without rushing.

### Continue Improving My Coding Skills

Finally, I would continue practicing HTML, CSS, and GitHub after completing the project. This project gave me a foundation, but I recognize that developing stronger coding skills will require continued practice.

Future improvements to the website could include additional pages, improved responsive design, more advanced CSS, and additional interactive features.

---

# 4. Key Lessons Learned

The biggest lesson I learned from this project is that creating a website involves more than simply writing code. Planning, organization, testing, troubleshooting, and revision are all important parts of the development process.

I also learned that mistakes are a normal part of learning how to code. When something did not work, I had to investigate the problem rather than assume that the entire project was incorrect.

The project also helped me become more comfortable with GitHub and online publishing. These skills can be useful beyond this class because version control and web development are commonly used in professional and technical environments.

---

# 5. Conclusion

Overall, the personal/professional portfolio project was a valuable learning experience. I successfully created and published a website while developing new skills in HTML, CSS, GitHub, and basic project management.

The challenges I experienced helped me understand the importance of planning, organization, testing, and problem-solving. If I completed the project again, I would spend more time planning the website structure, organize my files from the beginning, test each component as I build it, and allow additional time for troubleshooting.

This project provides a foundation that I can continue building on as I develop my technical and professional skills.
