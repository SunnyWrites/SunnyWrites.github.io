# Project Plan – Personal Portfolio Website

## 1. Project Overview

### Project Name

My Personal Portfolio Website - Susanna Unick

### Project Purpose

The purpose of this project is to create a professional personal website that introduces me, highlights my education and skills, and provides a way for potential employers or professional contacts to learn more about me.

### Project Goal

The goal is to create a functional, visually appealing, and easy-to-navigate website using HTML and CSS. The completed website will be published using GitHub Pages.

### Project Deliverables

The project will include:

* A professional homepage
* An introduction/about-me section
* Education and professional information
* Skills and interests
* Images or other visual elements
* A GitHub repository
* A published GitHub Pages website

# 2. Risk Analysis – TAME Framework

The TAME framework can be used to identify and manage risks that could affect the project.

## T – Transfer

Transfer a risk when another person, service, or system can take responsibility for handling it.

### Risk: Website hosting problems

GitHub Pages will be used to host the website. If there is a problem with hosting or publishing the website, I will use GitHub's documentation and support resources to troubleshoot the problem.

**Response:** Transfer/Share
**Action:** Use GitHub Pages documentation and technical support resources if needed.

---

## A – Avoid

Avoid a risk by changing the project plan so the risk is less likely to occur.

### Risk: Adding features that are too complicated

As a beginner learning HTML and CSS, adding advanced features could make the project difficult to complete on time.

**Response:** Avoid
**Action:** Keep the initial website focused on HTML, CSS, images, navigation, and basic functionality.

---

## M – Mitigate

Mitigate a risk by taking steps to reduce its likelihood or impact.

### Risk: Website errors

Incorrect HTML or CSS could cause parts of the website to display incorrectly.

**Response:** Mitigate
**Action:** Test the website regularly, check the HTML and CSS for errors, and view the website in a web browser after making changes.

### Risk: Project delays

Unexpected technical problems could cause the project to take longer than expected.

**Response:** Mitigate
**Action:** Break the project into smaller tasks and complete tasks according to the project schedule.

---

## E – Accept

Accept a risk when the risk is relatively small and there is no practical way to completely eliminate it.

### Risk: The website may look slightly different on different devices

Different browsers, screen sizes, and devices may display a website somewhat differently.

**Response:** Accept
**Action:** Test the website on multiple screen sizes when possible and make reasonable adjustments. Minor differences that do not affect usability will be accepted.

The project will be considered complete when:

* The website contains all required content.

* The project is available through GitHub Pages.
